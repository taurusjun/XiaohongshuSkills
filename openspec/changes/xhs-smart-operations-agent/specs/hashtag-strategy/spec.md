## ADDED Requirements

### Requirement: 话题标签按三层策略生成，精准标签优先使用标准译名
系统 SHALL 在内容生成阶段，为每篇文章输出结构化的三层话题标签策略，精准标签优先使用运营者维护的艺人名标准译名表。

> **背景：** 日本艺人名的中文译法非常不统一（田中美奈实 vs 田中美奈），LLM 直译的结果可能与小红书上真实流通的标签名不一致，导致精准标签实际上无搜索量。标准译名表由运营者维护，成本极低但对精准标签效果影响重大。

三层结构：
```
精准标签（1-2个）：艺人名、作品名、事件名
  → 流量池小，但目标受众精准，搜索转化率高
  → 使用 artist_name_map.json 中的标准中文译名，无对应时 LLM 自行翻译

垂类标签（2-3个）：所属细分领域
  → 流量池中等，账号标签权重积累的核心
  → 示例：#日本写真 #日本女星 #日系美女

泛流量标签（0-1个，可选）：
  → 流量池大但竞争激烈，仅在内容质量确实突出时使用
  → competition_count > 5000（近7天新发笔记数，由 trend_scanner 写入 topic_performance.competition_count）时不强加
```

标签生成方式：LLM 在 `generate_content` 阶段同步输出三层标签，以结构化 JSON 返回，不使用原有的单层 `tags` 字段。

#### Scenario: 精准标签提取（有明确艺人/作品名）
- **WHEN** 文章涉及具体艺人名字（如「田中美奈实」）或作品名（如「某写真集」）
- **THEN** 精准标签包含该艺人名和/或作品名（使用中文名，如有国内知名度），LLM 从日文原文中识别并翻译

#### Scenario: 精准标签缺失（泛话题资讯）
- **WHEN** 文章是综合性资讯，无特定单一艺人
- **THEN** 精准标签层降级为 1 个较精准的细分标签（如 #日本偶像 而非 #娱乐），垂类标签补充到 3 个

#### Scenario: 垂类标签与账号核心话题对齐
- **WHEN** `agent_strategy.json` 中配置了 `focus_topics`（如 `["写真", "日本女星"]`）
- **THEN** 垂类标签优先选取与 `focus_topics` 重叠的标签，保持账号垂类标签权重积累方向一致

### Requirement: 艺人名标准译名表维护
系统 SHALL 支持运营者在 `config/artist_name_map.json` 中维护艺人名的中日对照及标准中文译名，内容生成 prompt 优先使用表中的标准译名。

```json
{
  "田中みな実": "田中美奈实",
  "橋本環奈": "桥本环奈",
  "新垣結衣": "新垣结衣"
}
```

#### Scenario: LLM 使用标准译名生成精准标签
- **WHEN** 文章涉及艺人「田中みな実」，且 `artist_name_map.json` 中有对应条目
- **THEN** 精准标签使用「田中美奈实」（标准译名），而非 LLM 自行翻译的「田中美奈」

#### Scenario: 艺人不在译名表中时 LLM 自行翻译
- **WHEN** 文章涉及的艺人在 `artist_name_map.json` 中无对应条目
- **THEN** LLM 自行翻译，在飞书审批卡片中标注该精准标签「⚠️ 未在标准译名表中，请确认中文名是否为小红书上流通的通用名称」

### Requirement: 话题标签的竞争强度感知
系统 SHALL 在趋势扫描（`trend_scanner`）阶段，同步统计 XHS 各话题的近 7 天新发笔记数量，写入 `topic_performance.competition_count` 字段，辅助生成阶段的标签选取。

**数据来源：** `trend_scanner` 在扫描时，从 XHS 搜索结果页提取话题词条的笔记总数（或近 7 天新发数量），写入 `topic_performance.competition_count`（每次 07:00 全量扫描时更新）。

#### Scenario: 泛流量标签竞争过高时降级
- **WHEN** 某泛标签的 `competition_count` > 配置阈值（默认 5000 篇/周）
- **THEN** 标签生成 prompt 中该标签标记为「高竞争，谨慎使用」，LLM 根据内容评分决定是否添加；`candidate_score` < 3 的文章不添加高竞争泛标签

### Requirement: 运营者可在 Web UI 调整单篇标签策略
系统 SHALL 在文章详情页展示三层标签结构，运营者可修改任意一层的标签，修改后标签写回 `news.tags`（JSON 格式，区分三层）。

#### Scenario: 运营者修改精准标签
- **WHEN** 运营者在 Web UI 将精准标签从「田中美奈」改为「田中美奈实」（更正拼写）
- **THEN** `news.tags` 中精准标签更新，不影响垂类和泛流量标签，发布时使用更新后的标签

#### Scenario: 标签数量上限保护
- **WHEN** 系统/运营者添加标签后总数超过 8 个
- **THEN** 系统提示「超过 8 个标签可能影响分发，建议精简」，不强制阻止但 Web UI 显示警告
