# 标题 / 合并稿失败形态实锤册

10/31 一天内用户连查 4 篇（丢一个 key 或一句「这题目到底想表达什么」），全部是**机械门禁全绿、人一读就不对**。共同点：既有门禁测的全是形式（字数/假名/顿号/`##`/代词开头），没有一条测「信息有没有落地」。

每条的修法都一样：**收窄形态 → 全库回归量化误伤 → 三层落点固化**（脚本 FAIL/WARN ＋ review 扣分项 ＋ 判断口径文档）。只改文章不改门禁＝下次照犯。

## 一、五种形态与实锤

| 形态 | 实锤原句 | 坏在哪 | 现在拦它的东西 |
|---|---|---|---|
| 空壳落点 | 大西流星扮成夏尔，原作者也发了表情 | 「表情」是类别名词，读者拿不到画面。把「原作者盖章」这个最强信号降格成废话 | `SHELL_VERB_RE` / `SHELL_BARE` → FAIL |
| 术语当锚点 | 新单Under曲叫"编辑"，W中心是理理杏和莲加 | 三个日式黑话＋零团名＋人名缩昵称；粉丝觉得废话，路人 0 秒读不懂 | `JARGON_TITLE`＋锚点判断 → FAIL |
| 日文商品词 | 小嶋阳菜和LeSportsac联名，三款包全是别注 | 「别注」=別注（特别定制），中文没这个词；标题落在读者解码不了的词上 | `JP_LOANWORD_TITLE` → FAIL |
| 名单归纳写反 | 六期生被分散放进三列，没有整排塞在同一行 | 原文 3列目六人**整排都是六期生**，方向完全相反 | 无脚本门禁，只能靠「名单只许照抄」纪律 |
| 挂 related_keys 的译文 | 45场46.8万人…（正文 1132 字 / 主素材 3507 字 / 两条关联素材 0 事实落地） | related_keys 只是个 ID，没人检查素材内容进没进正文 | `merge_coverage.py` → 否决项退修 |

**标题被质疑的稿子，正文往往同时有编造或写反**——两件事一起查，别只改标题。

## 二、review 为什么放过了纯译文（8.6 分实锤）

| 漏洞 | 机制 |
|---|---|
| 密度否决项反向激励 | 规则是「正文 ≥ 素材 30%」。直译天然 100% 覆盖，密度满分；真做改写删了水词反而掉密度 |
| 「信息增量」有定义没判据 | 「多素材合并后的新视角=2分」写得很清楚，但没有可核验的东西，于是按「内容看着挺全」给了 1.7。纯译文按定义只能算 1 分区下沿 |
| 机械指标全绿=译文特征 | 字数/假名/顿号/`##`/标题，全都是译文天然能过的项 |
| 写和评是同一个人 | 自评自动偏袒自己写的东西，没有第二双眼 |

修法：信息增量维度改为跑 `merge_coverage.py`（采纳 ≥3 → 1.5~2.0；1~2 → ≤1.5；0 → ≤0.5 且触发否决项），并新增「合并稿整合度」否决项——**跑不出结果不许评分**。

## 三、merge_coverage.py 的校准值

`scripts/merge_coverage.py <40位key>`

| 参数 | 值 | 依据 |
|---|---|---|
| 同源重复：数字集合 Jaccard `numJ` | > 0.50 且 ≥3 个数字 | 5 家媒体同稿日期高度重叠 |
| 同源重复：3-gram Jaccard `gramJ` | > 0.55 | 逐字改写稿 |
| 中文要点实质覆盖 `cov` | ≥ 0.35 | 实测：真整合 0.50（大西流星稿借了原作者表情，无数字但确实用了）/ 顺带提到 0.19~0.23（浪花男子稿挂了两个素材却一个数字都没进正文） |

判定：所有独立素材的「独有数字采纳=0」**且**「cov 全部 < 0.35」→ ❌ 这不是合并稿，退修。

**已知局限**：同事件不同角度的稿子（如六期生落泪稿 vs 单曲公布稿）日期数字高度重叠，会被误判成「同源重复」而跳过统计——看标题人工判断，别把脚本当法官。中文数字已做转换（`十一个人` ↔ `11名` 能对上）。

## 四、被质疑时的动作顺序（用户口径：解释心路＝不及格）

1. **回原文逐行核对再开口**：拉 `content_ja` 全文，把人数·排位·日期·年龄·价格·期别逐条对一遍。
2. **先报不一致清单**：表格「原来写的 / 原文实际 / 性质（写反·无源·表述错）」，理由一句话收在后面。
3. **改文只传目标字段**，落库后复查：标题一致、正文字数、`publish_mode`、`related_keys` 条数。（`score_dims` API PUT 会静默忽略，只能 sqlite3 UPDATE。）
4. **把失败形态固化成门禁**，并在全库 `rewritten_title` 上跑一次误伤量化——FAIL 有误伤就先降 WARN 或收窄条件（10/23 标题人名门禁被推翻的教训）。
