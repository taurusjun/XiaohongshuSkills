# 中文评审标准

评分维度（各 2 分，满分 10 分）：

## 1. 爆发点（2分）
- 开头是否有吸引人继续读的钩子
- 2分：第一段就抓住读者，有冲突/悬念/名场面
- 1分：开头平淡但后续有亮点
- 0分：开头无关紧要或信息堆砌

## 2. 情绪价值（2分）
- 读者读完后的情绪反应（感动/愤怒/惊讶/共鸣）
- 2分：有明显情绪波动，有记忆点
- 1分：有情绪但不强烈
- 0分：纯信息陈述，看完没感觉

## 3. 信息增量（2分）
- 比日文原文多了什么新角度/深度
- 2分：有原文没有的解读、细节补充、多素材合并后的新视角
- 1分：基本覆盖原文要点但无延展
- 0分：比原文还少
- **⚠️ 这一维最容易给虚高（10/31 实锤）：`c0040119` 是纯主素材译文，仍被打 增1.7、总分 8.6 通过。** 译文天然「覆盖原文要点」，但按定义只能算 1 分区间的下限，不是 1.7。判分前必须回答：**这一句是原文哪一段的直译，还是别处素材/跨素材对位带来的？** 答不出「跨素材」就只能给 ≤1.0。
- **合并稿的可核验判据（有 related_keys 时强制）**：跑 `python3 scripts/merge_coverage.py <40位key>`，读它的「独立素材独有数字采纳数」。
  - 采纳 ≥3 → 可给 1.5~2.0（必须在 score_dims 里写出采纳了哪几条、贡献了什么）
  - 采纳 1~2 → 上限 1.5
  - 采纳 0 → 本维 ≤0.5，且触发下面的「合并稿整合度」否决项

## 4. 内容深度（2分）
- 是否有背景铺垫、人物关系、事件因果
- 2分：有完整背景交代，路人也能看懂
- 1分：有基础背景但不够
- 0分：默认读者什么都知道

## 5. 标题质量（2分）
- 标题是否有钩子、数字、矛盾
- 用 `xhs_title_len()` 检查标题字数：**一律 ≤20（news/story 同限）**，超过直接判 0 分
- 2分：有钩子+有信息+不超字数
- 1分：有钩子但超字数，或有信息但没钩子
- 0分：平淡/超字数/标题党
- **落点是空壳 → 最高 1 分（10/31 加）**：末分句以「发了表情/晒了照片/发文/发声/有反应」收尾＝把差异化信息降格成类别名词，读者拿不到画面。要求换成具体画面（「回了个星星眼」），见 `title-name-anchor-standard.md` 第九节。`batch_precheck.py` 已对「发/晒/回了+表情类名词」「发文/发声无宾语」直接 FAIL。
- **术语当锚点 / 人名缩昵称 → 最高 1 分（10/31 第二例）**：标题靠「新单／Under曲／W中心」撑信息、零团名，或把人名写成「理理杏」「莲加」这类昵称，一律扣分——粉丝觉得废话，路人 0 秒读不懂。压缩优先级：先砍术语，全名/团名/作品名最后砍。见同文档第十节。

## 被质疑时的三步核对（10/31）

用户对成品只丢一句疑问（「为什么会是这个标题」「你到底怎么搞出来的」「你看一下日语原文」）＝ **质量不合格信号，不是让你解释取名思路**。标准动作：

1. **先回原文逐行核对，再开口。** 拉 `content_ja` 全文，把正文里每个具体细节（人数·排位·日期·年龄·价格·期别）逐条对一遍。10/31 实测：被问标题时只讲了取名逻辑，隔一轮才按提示回原文，才发现正文把「3列目整排都是六期生」写成「六期生分散在三列」——**标题被质疑的稿子，正文往往同时有编造**，两件事一起查。
2. **先报不一致清单，再给改法。** 用表格「原来写的 / 原文实际 / 性质（写反·无源·表述错）」，理由放清单后面一句话收。不要先讲心路历程。
3. **改完立刻固化门禁。** 同一失败形态进 `batch_precheck.py` + 本文件扣分项 + 判断口径文档三处，并跑全库回归量化误伤（见 `title-name-anchor-standard.md` 第十/十一节）。只解释不改门禁 = 下次照样犯。
4. **用户是在逐层往下戳，不是只问一层。** 10/31 同一条稿被连戳四次：标题→表情空壳→没读日语原文（正文编造）→没读 ref（只翻译没综合）→最后「这种改写也能通过 review 吗」。**每次只修被指出的那一层，下一轮就会被戳更深的一层。** 收到第一句质疑时就把整条链一次查完：标题 → 正文逐条对 content_ja → related 素材用没用上（`merge_coverage.py`）→ 分数是否虚高。四层一起报，比被戳四次便宜。
5. **质疑 review 本身时，动作是「重算 + 扫同批」，不是辩解。** 具体三步：①按新判据把**旧分重算一遍**并在回复里给出该分数（10/31 旧版由 8.6 重算为 7.4）②用新判据**扫同批同期稿**，报「N 条带 related_keys 的稿子里 M 条零整合」并列出 key ③把新判据写进本文件 + 门禁脚本。只承认「评分有漏洞」不给新判据 = 下一次同样的稿子还是 8.6 过。

改动只传目标字段（`rewritten_title` / `rewritten_content`），落库后复查四项：标题一致、正文字数、`publish_mode`、`related_keys` 条数。

## 合并稿整合度（否决项，有 related_keys 时先跑，不通过直接退修）

**判据：这篇是不是「主素材译文 + 挂着 related_keys」。** 10/31 `c0040119` 实锤：正文段落顺序与 content_ja 一一对应，6 条关联素材一条事实都没用上，仍被打 8.6 分通过。

机械检查（先跑再评分，不跑不许评）：

```bash
python3 scripts/merge_coverage.py <40位key>
```

- 输出「独立素材 N 条，独有数字被正文采纳合计 0 个」+ ❌ 判定 → **退修**：把素材里的独家事实（人物原话/履历/时间线/第三方反应/交叉细节）织进骨架，或清空 `related_keys` 按单篇写。
- 全部 related 都是同源重复稿（脚本会标 `同源重复`）→ 不算否决，按单篇口径评，但 `related_keys` 应只留真正相关的，别挂一堆同稿凑数。

**人读的补充判据（脚本测不出来的部分）：** 合并稿必须有**至少一个只在这几篇合起来时才成立的判断**——比如「同一张站位表上，一个人的十年在收尾，八个人的第一年刚开始」这种把 A 稿的人物线叠到 B 稿的名单上才看得见的对位。把每篇素材的段落依次译完、末尾贴一段引语，不算整合，即使字数翻倍、密度爆表。

**为什么这条必须放在评分前：** 现有的密度否决项（正文 ≥ 素材 30%）对译文是**反向激励**——直译天然拿到最高密度，把原文信息点漏掉的改写反而更容易低分。所以「机器指标全绿」恰恰是译文的典型特征，整合度只能靠这条单独卡。

> 校准值（`numJ 0.50` / `gramJ 0.55` / `cov 0.35`）、同事件稿的误判边界、以及五种标题失焦形态的实锤，见 `references/title-failure-modes-casebook.md`。

## 内容密度（否决项，不通过则直接退修）
- 正文长度必须 ≥ 原始素材去重后的 **30%**
**计算方式：**
1. 收集：主素材content_ja + 每个related_keys素材的content_ja
2. 去重：把所有文本按 `。！？` 拆成句子，用 set() 去重后重新拼回
3. 计算：`xhs_len(正文) / xhs_len(去重后原文) * 100`
   - 正文和基准都用 `xhs_len()`（脚本 `scripts/xhs_word_count.py` 的 `xhs_len`函数：全角字符×1，半角字符×0.5，向上取整）
   - ❌ 不要用 `len()` 算基准 —— 半角英数被按×1算，密度偏低
   - ❌ 不要用 `re.findall(r'[\u4e00-\u9fff]')` 筛纯汉字 —— 漏日文假名
4. 低于30% → 判定"信息增量严重不足"，不进入评分流程，退回补充素材或合并关联条目
- 示例：柏木由纪主素材1626字 + 关联素材0 → 原文1626字。如果关联素材里有一段和主素材完全一样，去掉重复段后原文可能只剩1400字。正文605字 / 1400字 = 43.2%而非37.2%。

## 格式检查（否决项，不通过则直接退修）
- 正文不以标题行开头
- 用 ## 小标题分段
- 无 **加粗**
- 原话引用有三要素（谁+情境+说了什么）
- 日式表述已本地化（婚活→相亲 等）

### 日文商业/商品词对照表（10/31 加，标题与正文同查）

日文汉字词不等于中文词。**同一个写法在中文里不成立**的，一律换成中文表达；写进标题的直接 FAIL（`batch_precheck.py` 的 `JP_LOANWORD_TITLE`）。

| 日文 | 中文 | 踩坑实据 |
|---|---|---|
| 別注（べっちゅう） | 特别定制 / 定制版 | `5a9e366a` 标题「三款包全是别注」——中文读者不知道是什么 |
| ポーチ | 小包 / 收纳包 | 同篇正文把 ポーチ 写成「手袋」（中文=手提包），商品种类直接错 |
| 受注 | 接单 / 接受预订 | |
| 完売 | 售罄 | |
| 入荷 | 到货 | |
| 数量限定 | 限量 | |
| 新作 | 新作品 / 新款 | 中文很少单用「新作」 |
| 発売 / 予約 | 发售 / 预约 | 「発」已被新字体扫描拦；「予約」不会，靠本表 |

同类判断法：**这个词在中文里说得通吗？** 说不通就回 `content_ja` grep 原词按词义重译，不要按字形硬搬。
