## Phase A 落盘模式（本次全程使用的写法）

`mkdir -p /tmp/dXXX && python3 - << 'PYEOF'`（分隔符必须带引号），脚本内维护 `D = {'<key12>': "## 标题\n\n正文…"}`，循环写文件并**在同一次打印** `body 字数 / ## 数 / 假名数 / 破折号数`：

```python
for k,v in D.items():
    open(f'/tmp/d915/xhs_draft_{k}.md','w').write(v)
    body='\n'.join(v.split('\n')[1:])          # body-only，标题行不计（8/21 教训）
    jap=sum(1 for ch in v if '\u3040'<=ch<='\u309f' or '\u30a0'<=ch<='\u30ff')
    print(k, len(re.sub(r'\s','',body)), v.count('\n## '), 'kana=',jap, 'dash=',v.count('——'))
```

好处：一次调用写 3–6 篇，当场看到字数/小标题/假名，Phase C 零返工（本次 42 篇里只有 5 篇在写稿时就地扩充）。**story 的 `## ` 直接在字面文本里写死，不要事后降级。**

## Phase C 验证的两个坑（本次都踩到）

1. **落盘后的验证查询不能用 12 位前缀做 `key IN (...)`** ——
   `SELECT ... WHERE key IN ('cd8739984837', …)` 恒返回 0 行（DB 存 40 位全键），会误判「score_dims 全空、42 篇落盘失败」。正确写法：`WHERE substr(key,1,12) IN (...)` 或逐条 `WHERE key LIKE '前缀%'`。
2. **UPDATE 的目标行要先用前缀解析出全键** `SELECT key FROM news WHERE key LIKE 前缀||'%'`，再拿全键 UPDATE；`conn.row_factory = sqlite3.Row` 不设会报 `TypeError: tuple indices must be integers`。
