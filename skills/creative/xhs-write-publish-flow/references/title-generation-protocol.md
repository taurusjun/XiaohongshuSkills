# 标题生成协议（生成侧，10/31 整理）

> 门禁只能拦「已经犯过的」形态。10/31 一天内被用户连抓四例，四例都是**一条定稿直接入库**。
> 所以标题质量的正解不是继续加 blacklist，而是把「想标题」变成固定三步 + 强制三候选。

## 一、三步生成法（写 draft 首行的同一秒执行）

1. **选落点** —— 素材里最反直觉、最有画面的那**一个**细节。
   不是最概括的那一个，不是标题党最顺口的那个。
2. **选锚点** —— 人名 / 团名 / 作品名，放前 8 字（单人物稿）。
   群像、名单、公告、行业事件 → 事件当主语，人名可后置或省略。
3. **写 3 条候选**，分别套一种句式，**然后才选**：

| 句式 | 形状 | 例（当天定稿） |
|---|---|---|
| 画面型 | 具体物 + 具体动作/反应 | 大西流星扮夏尔，原作者回了个星星眼 |
| 对位型 | 同一支单曲/同一天上的反差 | 伊藤理々杏毕业前站C位，歌名叫《编辑》 |
| 引语型 | `主语：原话` | 板野友美被骂没教养，网友：我家也这样 |

**禁止一条定稿。** 三条写完跑 `batch_precheck.py`，过的第一条赢；三条都不过说明落点选错了，回素材重找。

## 二、当天四个反面案例（记住形状，不是记住词）

| 原标题 | 病 | 归属门禁 |
|---|---|---|
| 大西流星扮成夏尔，原作者也发了表情 | 落点空壳（发了什么类别，没说是什么样子） | `SHELL_VERB_RE` FAIL |
| 新单Under曲叫"编辑"，W中心是理理杏和连加 | 三个黑话 + 零团名 + 人名缩昵称 | 黑话无锚点 FAIL |
| 小嶋阳菜和LeSportsac联名，三款包全是别注 | 日文商品词当落点 | `JP_LOANWORD_RE` FAIL |
| 两年前站上C位时她在发抖，这次她说不怕了 | 通篇只有「她」，零主角名 | precheck 不拦，review 扣分（见 title-name-anchor-standard 第八节） |

共同点：**都不是用词问题，是「落点选错」**。选落点时问一句：这个落点读者能画出画面吗？画不出就换。

## 三、打分四问（替代「有钩子+有信息」这种模糊判词）

每问 0.5 分，合计 2 分，写进 review 的标题维度：

1. 锚点能检索吗？（人名/团名/作品名/可检索身份词，不是「她」「原作者」）
2. 落点是画面吗？（不是类别名词、不是日文词、不是黑话）
3. 有反差/冲突/悬念吗？（同一件事的两个面，或两方原话）
4. ≤20 字且无术语吗？

> 「有钩子+有信息」谁都给得出 1.8；四个是非题逼出证据。

## 四、同批句式疲劳（待实现，先人工看）

一批 ≥3 条用同一句式或同一开头（当天就出现三条「XX毕业前…」）→ 至少一条换句式。
机械化做法：`batch_precheck.py` 加一条「同 dir 内标题前 4 字重复 ≥3 → WARN」。

## 五、标题与正文一致性（待实现）

标题里的实词必须在 `rewritten_content` 里出现过。
理由：DB 标题多次张冠李戴，且「标题写了正文没有的事」是读者骂标题党的第一来源。
机械化做法：取标题中 2 字以上的中文词，与正文做包含判断，命中率 <60% → WARN。

## 六、数据侧（唯一能真正提高的一环，当前不通）

10/31 实测：9512 条里 **0 条**有 `xhs_note_id` / `xhs_impression` / `xhs_click_rate`。
→ 发布后数据回填链路是断的，所以现在所有标题规则都是**审美判断**，不是数据结论。

补齐顺序（做之前不要假装有数据依据）：
1. 发布流程回写 `xhs_note_id`；
2. 定期抓曝光 / 点击率 / 收藏；
3. 攒够 ≥50 条已发，按标题特征分组算 CTR（是否含人名 / 是否冒号引语 / 落点类型 / 字数区间），用真实差值替换本文件的假设。
