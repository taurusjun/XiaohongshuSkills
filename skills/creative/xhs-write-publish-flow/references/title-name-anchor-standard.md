# 标题锚点标准（改写标题的第一性原则）

10/23 一天内三次校准，用户原话依次是：**「标题总是缺失人物，不能一眼吸引粉丝」** → **「完全不符合你上面的标准」** → **「标题里带上人名并不是必须的」**。

最终口径：**人名是策略项，不是硬门槛。硬门槛是「标题必须有身份锚点」。**

## 一、硬门槛（只有两条）

1. **≤20 字**（CJK×1，拉丁/数字/假名×0.5）—— `scripts/xhs_word_count.py --check-title "<标题>" 20`
2. **不许以「他/她/他们」开头**（零身份锚点）—— `scripts/batch_precheck.py` 直接 FAIL

「身份锚点」= 下列任意一个：
- 人名（道枝骏佑）、团名（Snow Man / 樱坂46）、作品名（《黑色五叶草》）
- 身份词（「25人名单里唯一的日本偶像」「AKB17期生」「元AKB成员」）
- 事件本身当主语（「一个PHP漏洞，停了半个日本娱乐圈」）

**人名不是必须项。** `plan` 里的 `name` 字段只是自检提醒：填了但不含 → WARN；不填 → WARN。都不拦。

## 二、人名什么时候写、什么时候不写

| 题材 | 人名 | 理由 |
|---|---|---|
| 单人物访谈、爆料、私生活、反差型 | **写，且尽量靠前** | 粉丝是先扫名字认人的，扫不到直接划走 |
| 群像/名单/公告/行业事件（MAMA主持名单、PHP漏洞、排行榜、选秀合格名单） | 可不写 / 后置 | 事件本身就是卖点，人名会挤掉钩子，写成通稿腔 |
| 人名认知度低于事件（新人、素人、角色名） | 换团名 / 作品名 / 身份词 | 名字对外没有检索价值，占字数还伤钩子 |
| 名字占掉字数、钩子被挤没 | 保钩子，锚点降级为身份词 | 20 字是死的，先保会让人想点的那个 |

一句话判据：**0.5 秒里能不能同时告诉读者「这说的是谁/哪一类事」和「为什么值得点」。** 锚点管前者，钩子管后者。只有代词 = 两个都没做到。

## 三、10/23 审计实据 + 一刀切的反效果

第一批抽 36 条待发稿，**34 条标题不含主角名**，其中绝大多数是「他/她」当主语。批量改名锚点后出现反效果：**4 条原钩子更硬的被写平了**。

| 原稿（钩子硬、无锚点） | 我一刀切改（变通稿/变闷） | 最终定稿（保钩子+补锚点） |
|---|---|---|
| 25人名单里，站着唯一的日本偶像 | 道枝骏佑进MAMA主持名单，25人里唯一日本人 | MAMA主持25人，道枝骏佑是唯一日本偶像 |
| 45秒里，他的手一直没停过 | 寺田心输给阿部亮平，观众却在讨论他 | 寺田心45秒答题，手一直没停过 |
| 消失33年，她最后一部电影又被翻出来了 | 消失33年的樱田淳子，又被翻出来了 | 樱田淳子消失33年，最后一部电影被翻出 |
| 一个爱心emoji，两个男团粉丝打起来 | 井上瑞稀发了个爱心，两家粉丝吵翻 | 一个爱心emoji，两个男团粉丝打起来（原样保留，锚点=两个男团） |

**规律：补锚点只换主语，不许删原钩子的信息量。** 把「最后一部电影」这种具体元素换掉去腾字数，等于用通稿腔换掉钩子，比缺人名更亏。

## 四、门禁实现

| 项 | 判定 | 位置 |
|---|---|---|
| ≤20 字 | FAIL | `batch_precheck.py` / `--check-title` |
| 以他/她/他们开头 | **FAIL** | `batch_precheck.py`（10/23 加） |
| 落点是空壳（发/晒/回了+表情类名词、发文/发声无宾语） | **FAIL** | `batch_precheck.py`（10/31 加，见第九节） |
| 圈内黑话成堆且无团名/全名/作品名锚点（Under/W中心/新单/表题曲） | **FAIL** | `batch_precheck.py`（10/31 加，见第十节） |
| 圈内黑话 ≥2 个（锚点够） | WARN | 同上 |
| 标题含日文商品词（别注/受注/完売/入荷/予約/数量限定） | **FAIL** | `batch_precheck.py`（10/31 第三例，见 `references/title-failure-modes-casebook.md`） |
| 落点是泛反应词（炸了/引热议/上热搜/回应/表态） | WARN | 同上 |
| plan 未给 `name` | WARN | 同上 |
| 给了 `name` 但标题不含 | WARN | 同上 |

## 五、清库流程（批量返修历史标题）

1. 真待发用 `?publish_xhs=pending`；**`?publish_xhs=1` 不是过滤器**（返回全表 9047 条）
2. 逐条 `GET /api/news/<key>` 取 DB `title` + `rewritten_content`（钩子必须来自正文，DB 标题可能张冠李戴）
3. 写新标题 → `--check-title` → 超 20 就地改短
4. `PUT {"rewritten_title": t}` **只传标题**，不传正文
5. **四条一起验证**：标题一致、`len(rewritten_content)` 未变、`publish_xhs` 未变、`publish_method` 未变
6. 改完重跑新字体 + 假名扫描（新标题会引入新词）
7. 已发布(published)的稿改 DB 标题不会改已发的帖子，先看状态再动手

## 六、已知坑

- **一刀切要求人名会把好钩子写平**（10/23 四次实测，见第三节）——这是本条标准被推翻的直接原因。
- **砍人名零成本**：门禁只看代词开头，砍掉人名只要留了身份词就不报错。写的时候自己盯：这个身份词读者认不认得出是同一批人。
- **DB `title` 不等于事实**：DB 标题多次把人物/动作主体写错（8/2、8/5、8/6 案例）。补锚点前回 `rewritten_content` / `content_ja` 确认主角。
- **角色名不是人名**：「阿斯塔」「坂本」是角色，粉丝搜的是演员/声优。角色名当锚点时要配作品名（《黑色五叶草》BGM用了Snow Man）。
- **昵称/组合名/网络词不要猜译名**：`さや香`、`メロい`、`オズレーナー`、`かきさく` 这类无中文先例的，先 `search=<假名名>` 查 DB 既定写法，查不到就留日文并报给用户定。
- **21 字也会漏**：10/23 有 1 条 21 字旧稿（「村川绯杏再出发，把TGC的伸展台叫魔法之路」）一直躺在库里，返修时一并过门禁。

## 七、工具

- `scripts/batch_precheck.py` —— 写稿期门禁（字数/代词开头/空壳落点/圈内黑话/日文商品词/`name` WARN）
- `scripts/xhs_word_count.py --check-title` —— 唯一字数算法源
- `scripts/audit_pending_titles.py` —— 扫待发/已标记稿：缺人名候选、超 20 字、假名、日文新字体
- `scripts/scan_title_gates.py` —— 全库回归扫描（五类门禁，`--gate shell|pronoun|length|jargon|loan`）
- **生成侧方法见 `references/title-generation-protocol.md`** —— 选落点→选锚点→写 3 条候选（画面型/对位型/引语型）再选，禁止一条定稿；四问打分；同批句式疲劳与数据侧现状

## 八、写稿期执行缺口（10/29 三例，本批唯一返工来源）

**precheck 不拦「无主角名的标题」，只有 review 拦。** 标题维度规则是「不含主角名/团名（或只用她/他当主语）→ ≤1 分」，但 `batch_precheck.py` 只查「以他/她开头」这一种形态。写成「事件/处境当主语」的标题能过全部门禁，然后在 review 掉分、被迫回改 + 重入库一轮。

10/29 三篇同时踩（全是单人物稿，本应带名）：

| 首稿标题 | 问题 | 定稿 |
|---|---|---|
| 两年前她停下活动，答案到现在还没出来 | 主体是「她」+ 情境，读者不知是谁 | 二宫唯停工两年，答案到现在没出来 |
| 二列目正中间，是她和远藤樱 | 位置当主语，名字后置 | 贺喜遥香和远藤樱，站在二列目正中间 |
| 三天，20组，第一次 | 纯数字结构，零锚点 | 柏木由纪主持，20组偶像的联合舞台 |

**执行纪律：写 draft 首行的同一秒就判断题材**——单人物访谈/爆料/反差/私生活 → 人名放在前 8 字内；群像/名单/榜单/公告 → 事件当主语可以不写名。不要等 precheck（它不会报），也不要等 review（那时已入库一轮）。批量模式下把这三篇的定稿形态当模板：**「人物+动作」放前半句，钩子数字/反差放后半句**，20 字内能同时装下锚点与钩子。

批次实作细节见 `references/10-29-single-day-batch-flow.md`。

## 九、落点必须是画面，不是类别名词（10/31 实锤）

**失败案例**（`6810400b` 大西流星万圣节 cosplay，news）：

| | 标题 | 问题 |
|---|---|---|
| 原稿 | 大西流星扮成夏尔，原作者也发了表情 | 20 字内、人名+角色+身份锚点齐全、过了当时**全部**门禁，但读者不知道是什么表情 |
| 定稿 | 大西流星扮夏尔，原作者回了个星星眼 | 同一处信息换成画面，字数没变（17字） |

**根因不是「表情」这个词，是信息降格。** 两条素材合并后，相对同批其他成员的变装，这条唯一的差异化信息就是「《黑执事》原作者枢梁本人在 X 上回应了」——这是二创圈最强的盖章信号。写标题时方向选对了（拿差异化信息当钩子），但把最强信号压缩成了类别名词「表情」：读者拿不到画面，标题读起来像「对方顺手回了个表情包」。正文里明明点了名（「原作者枢梁发了眼睛发亮的表情」），标题反而退回抽象。

**通用原则：差异化信息必须落到「具体画面 / 具体身份」，不能落到「类别名词」。**

- 类别名词（等于没说）：表情、照片、动态、发文、发声、反应、互动
- 具体画面（读者能看见）：回了个星星眼、只发了一个表情没写字、把定妆照转了自己主页、评论区跟着念台词
- 具体身份：「原作者」→「黑执事作者」，有检索价值；身份词不能比正文更模糊

**写稿期三问（写首行同一秒自答，不等 precheck）：**

1. 这条素材区别于同批 / 同事件其它稿的**唯一**信息是什么？
2. 这个信息在标题里是「画面」还是「名词」？
3. 是名词 → 换成画面；换不出画面 → 这个信息不够硬，回素材里另找一个有画面的细节。

**门禁实现（`batch_precheck.py`，10/31）：**

- **FAIL**：`SHELL_VERB_RE` = `(也|还|又|只|就)?(发|晒|回|贴|po)(了|了个|了一张|了一段)?(表情包|表情|动态|照片|图)$`；`SHELL_BARE` = 末分句以「发文/发声」结尾（无宾语）
- **WARN**：末分句以「炸了 / 引热议 / 引发热议 / 引关注 / 引起关注 / 上热搜 / 反应 / 回应 / 表态」结尾
- **为什么分两层、为什么不做一刀切**：10/23 标题人名门禁被推翻的教训——把策略做成硬门槛会误伤好稿。10/31 实测全库 2247 条 `rewritten_title`：`SHELL_VERB_RE` 命中 **0** 条（零误伤），泛反应词 WARN **11** 条。反向验证：若按「以表情结尾即 FAIL」这条更粗的规则，会拦掉 `樋口日奈 61914b91f935「一句台词，两种表情」`、`bf54928ffbcc「被镜头抓到的表情」` 这类把空壳词当对比极/带具体物的**好**标题——所以精度优先，只拦「证据动词+类别名词」这一种真·空壳形态。
- 验证命令：`python3 scripts/batch_precheck.py --dir <draft目录> --spec <k12>=news:0:<ja>`，空壳命中会在 problems 里报「标题落点是空壳（<末分句>）」。

## 十、术语不是锚点，昵称不是名字（10/31 第二例）

**失败案例**（`c0040119` 乃木坂46 43单 Under 曲，story lf=1，862 字）：

| | 标题 | 结果 |
|---|---|---|
| 原稿 | 新单Under曲叫"编辑"，W中心是理理杏和莲加 | 20 字顶格，三个术语，零团名 |
| 定稿 | 伊藤理々杏毕业前站C位，歌名叫《编辑》 | 19 字，全名靠前，术语清零 |

**它坏在哪（四处，缺一处都不会这么难读）：**

1. **「新单」没有主语** —— 谁的 new single？路人扫过去接不上任何团。
2. **「Under曲」「W中心」是日式黑话** —— 对粉丝是高效压缩，对划屏路人是乱码。黑话是「压缩过的信息」，不是「不需要解释的信息」。
3. **「编辑」用直角/普通引号裹着** —— 读者以为是文档编辑，不知道是歌名。作品名要写《》。
4. **人名缩成昵称「理理杏」「莲加」** —— 粉丝认得，路人认不出；更糟的是**昵称能绕过 name 门禁**（plan 里填的是「伊藤理々杏」，标题里没有全名，却看着像有名字，precheck 只 WARN、review 判「有锚点」放行）。

**根因：20 字压缩时砍错了东西。** 当时为了塞进三个术语，先砍团名、再把两个人名缩成昵称——把「唯一能让路人定位」的成分砍了，把「只有粉丝才懂」的成分留了。**压缩优先级（从左到右先砍）：修饰语 → 术语 → 数字 → 具体动作 → 全名/团名/作品名。** 团名和全名是最后才动的东西。

**另一条口径：标题里的人名一律写全名。** 昵称只在正文里用。昵称既是弱锚点，又会骗过所有门禁。

**门禁实现（`batch_precheck.py`，10/31）：**

- **FAIL**：标题含 `JARGON_TITLE`（Under / W中心 / Wセンター / 新单 / 表题曲 / 标题曲 / 选拔曲 / 期生曲）**且**无锚点（name 候选含前 3 字匹配 / 书名号《》/ `GROUP_ANCHOR_RE`（xx46·xx48）/ `GROUP_ANCHOR_WORDS` 团名白名单）
- **WARN**：黑话 ≥2 个但锚点齐全（术语只该留最必要的一个）
- 白名单只为**放宽**（命中即算锚点齐全，不会多拦稿）：全库 2247 条实测，黑话 FAIL 仅 1 条（且那条本人名全名在 plan 里，实跑会通过）
- 反向验证：原稿标题稳定 FAIL、定稿 `伊藤理々杏毕业前站C位，歌名叫《编辑》` 通过；`日向坂46新单首周52.3万张再夺冠`、`≒JOY新单曲首周30.8万张` 这类「有团名+一个术语」的历史好稿不被误伤
- 全库回归：`python3 scripts/scan_title_gates.py --show 30` —— 把空壳/代词/超字数/圈内黑话四类门禁跑遍全库 `rewritten_title`，输出条数+样本。任何新门禁上线前跑一次，FAIL 有误伤就先降 WARN 或收窄条件。

## 十一、新增写作门禁的上线三步（用户口径：要机械拦截，不要只写 prose）

10/31 用户原话：「skill 怎么改能**保证**下次不犯这样错误」——只把教训写进文档等于没改，因为他下次不会读文档，机器会读脚本。所以写作类错误的固化顺序是：

1. **先收窄形态再写正则**：把失败案例的「末分句」单独拿出来看，只拦真·空壳形态（`发/晒/回了+类别名词`），不要拦整个词（`表情`）。判据：这条规则会不会误伤库里已有的好标题？
2. **全库回归量化误伤**：`scripts/scan_title_gates.py`。10/31 实测：粗版规则误伤 2 条好标题，窄版 FAIL 0/2247。**误伤为 0 才开 FAIL，有误伤一律降 WARN**——这是 10/23 标题人名门禁被推翻的直接教训（把策略做成硬门槛）。
3. **三层落点都要写**：`batch_precheck.py`（写稿期拦）＋ `chinese-review-criteria.md`（入库后扣分）＋ 本文件（判断口径与三问）。只改一层会出现「门禁过了、review 掉分、回改重入库」的返工，或反过来「review 说不该这么写、但脚本不拦」的扯皮。
4. 改完必须反向验证：拿**原始失败案例**当负样本（应 FAIL）、拿 2~3 条**同类好标题**当正样本（应 PASS）、再跑一次全库。三条都过才算上线。
