# 标题锚点标准（改写标题的第一性原则）

10/23 一天内三次校准，用户原话依次是：**「标题总是缺失人物，不能一眼吸引粉丝」** → **「完全不符合你上面的标准」** → **「标题里带上人名并不是必须的」**。

最终口径：**人名是策略项，不是硬门槛。硬门槛是「标题必须有身份锚点」。**

## 一、硬门槛（只有两条）

1. **≤20 字**（CJK×1，拉丁/数字/假名×0.5）—— `scripts/xhs_word_count.py --check-title "<标题>" 20`
2. **不许以「他/她/他们」开头**（零身份锚点）—— `scripts/batch_precheck.py` 直接 FAIL

「身份锚点」= 下列任意一个：
- 人名（道枝骏佑）、团名（Snow Man / 樱坂46）、作品名（《黑色五叶草》）
- 身份词（「25人名单里唯一的日本偶像」「AKB17期生」「元AKB成员」）
- 事件本身当主语（「一个PHP漏洞，停了半个日本娱乐圈」）

**人名不是必须项。** `plan` 里的 `name` 字段只是自检提醒：填了但不含 → WARN；不填 → WARN。都不拦。

## 二、人名什么时候写、什么时候不写

| 题材 | 人名 | 理由 |
|---|---|---|
| 单人物访谈、爆料、私生活、反差型 | **写，且尽量靠前** | 粉丝是先扫名字认人的，扫不到直接划走 |
| 群像/名单/公告/行业事件（MAMA主持名单、PHP漏洞、排行榜、选秀合格名单） | 可不写 / 后置 | 事件本身就是卖点，人名会挤掉钩子，写成通稿腔 |
| 人名认知度低于事件（新人、素人、角色名） | 换团名 / 作品名 / 身份词 | 名字对外没有检索价值，占字数还伤钩子 |
| 名字占掉字数、钩子被挤没 | 保钩子，锚点降级为身份词 | 20 字是死的，先保会让人想点的那个 |

一句话判据：**0.5 秒里能不能同时告诉读者「这说的是谁/哪一类事」和「为什么值得点」。** 锚点管前者，钩子管后者。只有代词 = 两个都没做到。

## 三、10/23 审计实据 + 一刀切的反效果

第一批抽 36 条待发稿，**34 条标题不含主角名**，其中绝大多数是「他/她」当主语。批量改名锚点后出现反效果：**4 条原钩子更硬的被写平了**。

| 原稿（钩子硬、无锚点） | 我一刀切改（变通稿/变闷） | 最终定稿（保钩子+补锚点） |
|---|---|---|
| 25人名单里，站着唯一的日本偶像 | 道枝骏佑进MAMA主持名单，25人里唯一日本人 | MAMA主持25人，道枝骏佑是唯一日本偶像 |
| 45秒里，他的手一直没停过 | 寺田心输给阿部亮平，观众却在讨论他 | 寺田心45秒答题，手一直没停过 |
| 消失33年，她最后一部电影又被翻出来了 | 消失33年的樱田淳子，又被翻出来了 | 樱田淳子消失33年，最后一部电影被翻出 |
| 一个爱心emoji，两个男团粉丝打起来 | 井上瑞稀发了个爱心，两家粉丝吵翻 | 一个爱心emoji，两个男团粉丝打起来（原样保留，锚点=两个男团） |

**规律：补锚点只换主语，不许删原钩子的信息量。** 把「最后一部电影」这种具体元素换掉去腾字数，等于用通稿腔换掉钩子，比缺人名更亏。

## 四、门禁实现

| 项 | 判定 | 位置 |
|---|---|---|
| ≤20 字 | FAIL | `batch_precheck.py` / `--check-title` |
| 以他/她/他们开头 | **FAIL** | `batch_precheck.py`（10/23 加） |
| plan 未给 `name` | WARN | 同上 |
| 给了 `name` 但标题不含 | WARN | 同上 |

## 五、清库流程（批量返修历史标题）

1. 真待发用 `?publish_xhs=pending`；**`?publish_xhs=1` 不是过滤器**（返回全表 9047 条）
2. 逐条 `GET /api/news/<key>` 取 DB `title` + `rewritten_content`（钩子必须来自正文，DB 标题可能张冠李戴）
3. 写新标题 → `--check-title` → 超 20 就地改短
4. `PUT {"rewritten_title": t}` **只传标题**，不传正文
5. **四条一起验证**：标题一致、`len(rewritten_content)` 未变、`publish_xhs` 未变、`publish_method` 未变
6. 改完重跑新字体 + 假名扫描（新标题会引入新词）
7. 已发布(published)的稿改 DB 标题不会改已发的帖子，先看状态再动手

## 六、已知坑

- **一刀切要求人名会把好钩子写平**（10/23 四次实测，见第三节）——这是本条标准被推翻的直接原因。
- **砍人名零成本**：门禁只看代词开头，砍掉人名只要留了身份词就不报错。写的时候自己盯：这个身份词读者认不认得出是同一批人。
- **DB `title` 不等于事实**：DB 标题多次把人物/动作主体写错（8/2、8/5、8/6 案例）。补锚点前回 `rewritten_content` / `content_ja` 确认主角。
- **角色名不是人名**：「阿斯塔」「坂本」是角色，粉丝搜的是演员/声优。角色名当锚点时要配作品名（《黑色五叶草》BGM用了Snow Man）。
- **昵称/组合名/网络词不要猜译名**：`さや香`、`メロい`、`オズレーナー`、`かきさく` 这类无中文先例的，先 `search=<假名名>` 查 DB 既定写法，查不到就留日文并报给用户定。
- **21 字也会漏**：10/23 有 1 条 21 字旧稿（「村川绯杏再出发，把TGC的伸展台叫魔法之路」）一直躺在库里，返修时一并过门禁。

## 七、工具

- `scripts/batch_precheck.py` —— 写稿期门禁（字数/代词开头/`name` WARN）
- `scripts/xhs_word_count.py --check-title` —— 唯一字数算法源
- `scripts/audit_pending_titles.py` —— 扫待发/已标记稿：缺人名候选、超 20 字、假名、日文新字体
