# 已写稿的合并更新（Merge-Update）流程

## 什么时候用

场景：同一个人物/事件的旧稿已有 rewritten_content 但未发布（preselected=1 但 xhs_note_id 为空），新素材提供了 2-3 个核心补充信息点（非全新事件）。

判断条件：
- ✅ 同一人物
- ✅ 旧稿已写未发
- ✅ 新素材是后续细节/新角度（非全新独立事件）
- ✅ 补充信息点 ≤ 3个

## 流程

### 第1步：读旧稿
```python
curl -s http://127.0.0.1:5000/api/news/<old_key> | python3 -c "import sys,json; print(json.load(sys.stdin).get('rewritten_content',''))"
```

### 第2步：读新素材content_ja
```python
curl -s http://127.0.0.1:5000/api/news/<new_key>
# 看 content_ja 字段，找旧稿中没有的新信息点
```

### 第3步：找到嵌入位置
不要重写全文。找到旧稿中最自然的插入点：
- 如果有新场景 → 加一个##小标题段落
- 如果是新细节 → 嵌入到现有段落中
- 如果是时间线补充 → 放到对应时间节点后

### 第4步：段落级增量修改
只改那 1-3 处，不要动其他内容。

### 第5步：更新related_keys
在旧稿的 related_keys 中追加新素材key，逗号分隔。

### 第6步：验证
确认旧稿的 rewritten_content 长度仅增加了新增信息量，没有大段替换。

---

## 合并模式速查

### 模式A：信息嵌入（原有）
**场景：** 新素材补充 2-3 个旧稿遗漏的细节/引语（非时间线事件）
**做法：** 找到最自然的段落嵌入新细节，段落级修改
**案例：** 大野智纹身——新素材补充了「纹身图案是自己画的下图」「最后演唱会唱了カイト」
**结果：** 1108 → 1189字，+81字

### 模式B：开头覆盖（6/19新增）
**场景：** 新素材是同一事件的时间线前一个节点（开箱惊喜vs接到电话），旧稿从"后"开始写
**做法：** 将新素材场景作为开篇hook写在旧稿前面，旧稿正文不动。新稿标题相应改为覆盖两个场景
**案例：** 井上和→玩具5声优。旧稿从「接到电话」写起，新素材补充了「开箱惊喜落泪」场景
**操作：** 新场景作为第1段开篇→过渡句→旧稿正文。related_keys指向新素材key
**标题策略：** new开篇hook + 旧稿核心内容，合并后标题覆盖两个场景
**结果：** 1094 → 1049字（旧稿内容全部保留，新场景前置，去掉了旧稿中与今天重叠的「接到电话」描述）

### 模式C：独立新稿（6/19新增）
**场景：** 新素材是同一人物的不同角度的完整新事件，独立性强到足以自成一篇
**判断标准：**
- 新素材有独立的故事弧线（起承转合+引语+场景），不依赖旧稿的背景才能理解
- 旧稿和新闻稿合并后文章过长（>1200字）或结构散架
- 新素材的核心hook与旧稿完全不同（如A是BIRTHDAY LIVE整体叙事，B是广播中的单人回忆）
**做法：** 写独立新稿到新素材key，related_keys指向旧稿key。旧稿保留不变
**案例：** 贺喜遥香。旧稿「贺喜遥香的Center曲，是梅泽美波最后一次」(BIRTHDAY LIVE叙事，约400字)。今日新素材(别硬撑+入坑曲)是广播节目的单人回忆，有独立故事弧线→写新稿并关联旧稿
**结果：** 两稿共存，互不冲突

### 模式选择决策树
```
新素材和旧稿是同一事件的不同时间节点？
  ├─ 新素材是**更早**的时间节点（如惊喜公布vs接到电话）→ 模式B（开头覆盖）
  └─ 新素材是**后续**事件（如旧稿预告、新稿结果）→ 旧稿预设为0，新稿覆盖（见场景B）
新素材是同一人物同一事件的补充信息点？
  ├─ 信息点≤3个，可嵌入旧稿现有段落 → 模式A（信息嵌入）
  └─ 信息点>3个，嵌入后结构散架 → 模式C（独立新稿）
新素材是同一人物但**不同事件/不同角度**的完整故事？
  └─ → 模式C（独立新稿）
多条新素材来自**同一源头**（同一节目/同一采访的不同片段）？
  └─ → 先判断是合并写1篇还是独立成多篇（见下方）
```

### 同一源头的多条新素材整合（6/19新增）

**场景：** 多条新素材来自同一个节目/同一期采访的不同片段，被拆成多条独立条目入库。

**典型案例：**
- 贺喜遥香：别硬撑（5.0分）+ 入坑曲毕业曲（5.0分），均来自同一期《乃木坂LOCKS!》
- 柏木由纪（之前案例）：6条来自同一期《ぽかぽか》

**判断方法：** 检查各素材的content_ja开头是否指向同一个节目/同一天/同一个主持环节。
- 是（同一源头）→ 判断合并还是独立
- 否（不同源头）→ 各自独立评估

**合并写1篇的判断条件：**
1. ✅ 多条素材的hook可以有机串联（别硬撑+入坑曲同属"毕业传承"主题）
2. ✅ 合并后的字数控制在合理范围（<1200字）
3. ✅ 各条素材有不同侧重点，不是同一信息角度复述
4. ❌ 如果各条素材hook完全不同且各自足以成篇 → 独立写多篇

**做法：** 选择核心hook最强者作为标题，其余素材作为##小标题段落嵌入。related_keys包含所有未直接使用的素材key。
