# 批量破折号修复策略（7/1经验）

当renwei拒绝原因以 **格式痕迹（破折号）** 为主（10-17处/篇），逐行修复效率太低。采用**全文件批量替换**策略更高效：

## 操作步骤

1. **检查当前破折号数量**
   ```bash
   grep -c "——" /tmp/xhs_draft_xxx.md
   ```

2. **批量替换破折号→句号**（用于引语前/后或独立短句）

3. **批量替换破折号→冒号**（用于解释/举例/引出）

4. **批量替换破折号→逗号**（用于转折/承接关系）

5. **引语内的破折号**（在`""`/`「」`内且是被采访者原话）不修改——标记为「引语内命中，非AI生成」

## 效果

7/1 session：
- S1（龟梨）：17处→3处破折号 → exit 2 ✅（3轮patch）
- S2（目黑莲）：6处→1处破折号 → exit 2 ✅（1轮批量改写）
- S3（KAMIGATA）：10处→1处破折号 → exit 2 ✅（1轮批量改写）
- A1（流媒体）：10处→1处破折号 → exit 2 ✅（1轮批量改写）
- A2（金村）：17处→0处破折号 → exit 0 ✅（1轮批量改写）

关键效率点：与其逐行patch，不如直接重写整个draft文件将所有`——`替换为句号/冒号/逗号。因为draft文件通常800-4000字，一次性写一个新版本比做10+次patch快得多，且不易遗漏。
