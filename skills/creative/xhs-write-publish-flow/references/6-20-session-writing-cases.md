## 发现的问题

### 1. update.sh 端口错误
- update.sh 写的是 `5001`，webapp 实际跑在 `5000`
- 已修复（6/20 patch）
- 导致之前所有 PUT 请求返回 `{"ok":true}` 但数据没落盘

### 2. API返回的key与DB不一致
- 全量列表API返回的key与DB实际存储的key**后缀不同**
- 示例：API返回 `92307c95b999923ed229decc74b4cf9f9634214e`，DB中存的是 `92307c95b999f69ff3c9ec7eb1a62b69d9d42966`
- 用API返回的key去PUT会落空（`{"ok":true}` 但DB不变）
- **解决方案**：入库前从sqlite3取key，不要从API取。或用sqlite3 UPDATE直接写
- 修复代码：`db.execute('UPDATE news SET preselected=1, publish_mode=?, rewritten_title=?, rewritten_content=? WHERE key=?', ('rewritten', title, content, key))`

### 3. 全部稿件正文首行都有`# 标题`
- 因为draft文件第一行是markdown标题，入库时用 `open().read()` 整块写入
- 7篇稿全部要批量修
- 修复：Python逐篇 `lines = content.split('\\n'); new_content = '\\n'.join(lines[1:]).strip()`
- 教训：draft文件必须分两段——标题是标题，正文是正文，不能混在一个文件里整块读

### 4. 篠田麻里子内容密度29.3%（略低于30%）
- 原因：content_ja特别长（2983字），短news只有875字
- 补充了2个新段落（TVer配信策略+TVer缩略图细节）后达到35.4%
- 教训：短news在content_ja特别长时需额外检查密度。补充素材原文中的真实场景细节而非虚构
