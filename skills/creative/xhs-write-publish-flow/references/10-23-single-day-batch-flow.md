## 2. 新坑（三个）

### 坑1：`open(fn,'w').write(open(fn).read().replace(...))` 把 draft 写成空文件
一行式「读→替换→写」在 python 里是**先执行 `open(fn,'w')`（立即 truncate）再执行 `open(fn).read()`**，读到的是空串，落盘就是 0 字节。本次 `be1ed196` 因此变成空文件，precheck 报「缺首行 `## 标题` / 密度 0.0%」才发现（内容需整篇重写）。
**正确写法：** 先读进变量再写。
```python
c = open(fn).read()
open(fn, 'w').write(c.replace(old, new, 1))
```

### 坑2：`substr(key,1,12) IN (...)` 里塞 8 位前缀 → 恒 0 行，误判「score_dims 全空」
本次评分落盘 15/15 成功，验证查询写成 `WHERE substr(key,1,12) IN ('9278b8e2', ...)` 返回 0 行，一度以为落盘失败。**验证/回查统一用「与手上前缀同位数」的 substr**，或直接 `WHERE key LIKE '前缀%'`。9/15 已记过同形态，这次是 8 位前缀版本。

### 坑3：候选池里 `body>900` 的 story 必须在排期前压到 ≤950
`0fe16e2d` 初稿 body 1042 字（story lf=1，900±50 口径），被选中排期前必须压缩：两轮共删约 135 字（合并「团体表情」解释、删掉「找存在感/被针对」一段），落到 907 才排。**压缩后必须重跑 batch_precheck + renwei + 重入库 + 覆盖 score_dims**——本次 renwei 从 exit0 重跑到 0 命中，score 8.9。
