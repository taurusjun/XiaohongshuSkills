# Story Draft 字数不足800时的patch扩充技术

## 适用场景

format=story 且 is_long_form=1 的素材已写出draft，字数在400-799之间（未达800字合格线），且已完成##小标题分段。

**不要在此时重写全篇。** 用patch定向扩充即可。

## 五类扩充素材源（按优先级排列）

### 1. 从content_ja加更多引语/细节（最高效）

读完content_ja后，每次写draft时自然留下了大量未使用的原始信息。回去翻原文，找：

- 被采访者原话中未被使用的引语段 → 插入到相关段落
- 场景描写细节（天气、服装、场所、氛围）
- 数字信息（人数、时间、金额、年龄）
- 事件经过中被省略的中间环节

**案例（7/27 宫胁咲良手工包 453→861字）：**
- 原文只写了「她用韩语写道……日文配文中说这是……」
- 扩充：加了「她曾在节目中展示过钩针编织的小物」+「从'玩玩'到'作品'的质变」+「原设计者本人的留言」
- 结果：+150字，且补充了人物背景信息

### 2. 展开已有引语的上下文

如果某句引语只有单句，可以考虑把引语前后的对话/背景补上：

- 谁问的？什么场景下说的？
- 她说这句话时表情/语气如何？
- 周围人有什么反应？

**案例（7/27 藤嶌果步 746→856字）：**
- 原文只写了同期拿来炸鸡安慰她
- 扩充：加了「担任Center也让工作范围扩展」+「遇到了前辈与田祐希给的Center建议」
- 结果：+110字来自原文中被省略的「外番组」经历

### 3. 加粉丝/公众反应

许多原文末尾都有粉丝在SNS上的评论——这是天然的扩充素材：

- 直接引用1-2条有代表性的粉丝评论
- 翻译为中文，用引号包裹
- 注意：只选有信息量的（不是单纯吹捧），如「终于等到了」「涂唇膏的他是最可爱的」

### 4. 加人物背景/履历

从原文底部的人物profile段提取信息，嵌到正文靠后位置：

- 年龄、出身地、出道时间
- 之前的代表作/重要经历
- 数据（粉丝数、销售数据、比赛成绩）

**注意：** 不要写成简历格式（时间线堆砌），要嵌入叙事——如「从XX出道，经过XX，再到XX——但今天她展示的是另一面」。

### 5. 场景对比/反差描写

原文如果有「看起来A但实际上B」的结构，可以补充对比细节：

- 「所有人都在X的时候，只有她在Y」→ 分别写X和Y的细节
- 「角色A是B，但本人是C」→ 分别写B和C

## 操作流程

```bash
# 1. 查当前字数
python3 ~/.hermes/skills/creative/xhs-write-publish-flow/scripts/xhs_word_count.py "$(cat /tmp/draft.md)"

# 2. 读全文找扩充点
read_file /tmp/draft.md

# 3. 回原文找可用素材
read_file /tmp/source_content_ja.md   # 之前下载好的content_ja

# 4. patch扩充（选原文中信息密度最高的段落扩充）
## 方法A：在段尾加引语/细节
patch path=/tmp/draft.md old_string="段尾原文句" new_string="段尾原文句+"新加的内容""

## 方法B：在小标题后加段落
patch path=/tmp/draft.md old_string="### 小标题\n\n现有内容" new_string="### 小标题\n\n现有内容\n\n新段落内容"

# 5. 验证字数+假名
python3 .../xhs_word_count.py "$(cat /tmp/draft.md)"
python3 -c "c=open('/tmp/draft.md').read(); jap=sum(1 for ch in c if '\u3040'<=ch<='\u309f' or '\u30a0'<=ch<='\u30ff'); print(f'假名:{jap}')"

# 6. 重跑renwei确认（扩充后可能改变renwei判定）
ALL_PROXY="" python3 ~/.hermes/skills/writing/renwei-writing/scripts/renwei-pre-commit.py /tmp/draft.md
```

## 效率原则

- 每篇扩充目标：800-1000字之间即可，不需要一次拉到1200
- 一次patch+130~200字是最自然的速度（加太多会破坏叙事节奏）
- 读完content_ja后立即做的扩充才是最有效的（信息新鲜）
- 积累10+篇draft再回头扩充，每篇都要重新读content_ja，效率折半
