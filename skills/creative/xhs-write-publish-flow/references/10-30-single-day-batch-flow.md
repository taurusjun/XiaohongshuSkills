## 1. 删段把下一行 `##` 粘进段尾（新形态，precheck 不报）

为了把 928 字压到 ≤900（post 路由要求），删掉了某小标题下唯一的一段：

```python
c.replace("棚里的池田直人听到房租的数字…不合常理。\n\n", "")   # ← 连带吃掉了到下一标题的换行
```

结果前一段与下一个标题被拼成一行：

```
…第9集播的是10月22日这一期，主角是她。## 体脂从24%降到19%
```

- `line.startswith('## ')` 数不到它 → precheck 报 `##=2`（原本 3），**不说原因**，字数/密度/假名全部正常。
- 这是 10/28「相邻两个 `##` 中间无正文」的姊妹形态：那个是两行标题相邻，这个是标题被粘进段尾。

**自检两条**：`grep -n '^## '`（看标题是否独占行首）+ `grep -n '。## '`（看粘连）。删除任何段落时，把下一标题前的 `\n\n` 写回去；删掉某标题下唯一一段会留下「空标题」，要么补一段正文要么连标题一起删。

## 2. precheck 报「日文新字体 ['み']」= 主角名是假名，不是字体问题

`渡部いずみ`（A12 隆胸稿）与 `優木まおみ`（S4）双双命中 `日文新字体 ['み']`，kana 计数同时报 3。
`み` 不是新字体字，命中来自**人名里的单字假名**（まおみ / いずみ）。处理顺序照「主体人名本身就是假名」条：

1. 先查 DB 历史中文写法（本次两例都是新人物，无先例）；
2. 自定汉字读法并全文统一：`優木まおみ → 优木真央美`、`渡部いずみ → 渡部泉`；
3. 同时清掉假名族专名：`しんめいP → 新明P`（4 假名，一本哲学书作者）、`アイガトー → 伊贺糖`（5 假名，点心名，写在 `##` 标题里同样计数）、`「ねーねー」→ 直接催他`。

**判据：scan 报出来的若是单个假名字符（み/こ/ゆ…），先去主角名里找，不要当字体问题逐字替换。**

## 3. 补字：整段补，不要延长句子（本次最大耗时来源）

中文落笔比预估短得离谱，本轮反复补字：15 篇里 12 篇首写不足，A2 一篇补了 3 轮（614→790→834）。

| 补字手法 | 实测增量 |
|---|---|
| 把已有句子写长一句（`rep` 短句→长句） | **+20~40 字/次**，极易反复迭代 |
| 新增一整段带 `##` 小标题的正文 | **+120~250 字/次**，一轮到位 |

**目标换算（xhs_content_len = 字符数，换行不计）：** story 想要 body ≥850，draft 全文（含首行标题）应 ≥880；`len(text)` 里中文 1 字=1，不要用"我大概写了 800 字"的感觉判断——本次首写估计普遍高估 40%。
**纪律：每篇 draft 落盘后立即跑一次 `xhs_word_count.py`，不足就整段补，别攒到批末。**

## 4. 排期后必须单独核 `gallery_images`（不只信 `--apply` 的 verify OK）

`pub_time_plan.py --keys … --apply` 的图集下载分支本次 5/5 静默 skip：

```
skip (…, '09:00', '2026-10-31 08:57') -> URL can't contain control characters. "/api/gallery-download/('d39eadc0…
```

改用 `POST /api/gallery-download/<40位key>` 逐条补踢，5 条都返回 `{"status":"started"}`，但 60 秒后 `gallery_images` 仍为 `[]`。

**所以：`--apply` 的 `[verify OK]` 只覆盖 `xhs_pub_time` + `publish_xhs`，不覆盖图片。** 排期收尾必查：

```sql
SELECT substr(key,1,12), length(gallery_images), xhs_pub_time
FROM news WHERE xhs_pub_time LIKE '<明天>%';
```

`length(gallery_images)=2` 就是空数组 `[]`。有 `gallery_url` 的条目图片还是空 → 排期生效但发文前需人工确认封面图。
