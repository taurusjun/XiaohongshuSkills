# 6/27 改稿循环案例：renwei拒绝→恢复实战

## 场景

影山优佳「14岁裁判证」V2改稿（A4）提交 renwei-pre-commit.py 时返回了 exit code 1（拒绝入库）。

## 原因

1. **意义拔高聚集** — 末段总结「没走那条最快路径，选了最笨的路」+ 中间段「竹内能被接受，建立在影山铺好的路上」→ 两个格言公式句触发了同类≥2的聚集判定
2. 破折号5处仅属于格式痕迹类，不参与聚集，不需要处理

## 修复路径（2轮通过）

### 第1轮：砍掉中间段的格言公式句

原句：`但竹内能被接受，实际上是建立在影山铺好的路上。「偶像/演员也能真正懂球」这个前提被证明之后，更多的跨界者有了入场券。`

改后：`但竹内能被接受，某种程度上是因为影山先走了这条路。`

结果：仍然失败（意义拔高还有2处）

### 第2轮：砍掉结尾总结 + 压缩中间段

原中间段：
```
竹内凉真...两人走的是完全不同的路线——一个在配信平台上深耕内容，一个在地面波扩散现场氛围。

但竹内能被接受，某种程度上是因为影山先走了这条路。
```

改后：
```
竹内凉真...两人路线完全不同，但同届世界杯并行走着。
```

原结尾：
```
从14岁在地方球场吹哨子的少女，到世界杯演播室和职业解说一起分析战术——她没走那条「偶像转型女主持」的路。
```

改后（用素材原生引语收尾）：
```
从14岁在地方球场吹哨，到世界杯演播室分析战术。素材里有一段话：「影山优佳这一个体所积累的东西，正在一点一点地改写整个行业的图景。」
```

结果：通过（exit code 2）

## 规律

1. 意义拔高聚集的核心理由是**作者在替读者做总结**——任何「X是Y」「这条路是Z」的判断句式都有风险
2. 修复优先做减法：砍掉判断句，保留事实描写
3. 用素材原生引语（尤其带引号的）代替作者总结最安全
4. 破折号聚集判定阈值比意义拔高严格得多——5个破折号都不判定聚集，但2个意义拔高就判定

## 批量破折号修复策略（7/1经验）

当renwei拒绝原因以 **格式痕迹（破折号）** 为主（10-17处/篇），逐行修复效率太低。采用**全文件批量替换**策略更高效：

### 操作步骤

1. **检查当前破折号数量**
   ```bash
   grep -c "——" /tmp/xhs_draft_xxx.md
   ```

2. **批量替换破折号→句号**（用于引语前/后或独立短句）
   ```
   替换目标：`XX。"YY"` 或 `"YY"。XX` 
   ```

3. **批量替换破折号→冒号**（用于解释/举例/引出）
   ```
   替换目标：`主要信息：细节`
   ```

4. **批量替换破折号→逗号**（用于转折/承接关系）
   ```
   替换目标：`A不是B，而是C`
   ```

5. **引语内的破折号**（在`""`/`「」`内且是被采访者原话）不修改——标记为「引语内命中，非AI生成」

### 效果

7/1 session：
- S1（龟梨）：17处→3处破折号 → exit 2 ✅（3轮patch）
- S2（目黑莲）：6处→1处破折号 → exit 2 ✅（1轮批量改写）
- S3（KAMIGATA）：10处→1处破折号 → exit 2 ✅（1轮批量改写）
- A1（流媒体）：10处→1处破折号 → exit 2 ✅（1轮批量改写）
- A2（金村）：17处→0处破折号 → exit 0 ✅（1轮批量改写）

关键效率点：与其逐行patch，不如直接重写整个draft文件将所有`——`替换为句号/冒号/逗号。因为draft文件通常800-4000字，一次性写一个新版本比做10+次patch快得多，且不易遗漏。
