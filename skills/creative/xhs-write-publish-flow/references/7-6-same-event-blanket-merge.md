# 同事件多条素材合并写稿（7/6经验）

## 触发条件

用API `search=` 搜同人物时，发现同一天/同事件有 ≥2 条入库记录，标题明显指向同一件事的不同角度报道。

典型模式：
- 同一场记者会的不同媒体报道（每条侧重不同发言）
- 同一发言的"当事人说" + "网友反应" + "圈外人蹭热点"的连锁反应
- 同一事件的不同追踪角度

## 判定流程

1. 通读每条素材的 content_ja，确认是否是同一事件的不同报道
2. 判断合并后的信息增量是否大于单篇：
   - 如果每条都是完全复读同一段话 → 选 content_ja 最长的写单篇，不合并
   - 如果各有不同角度（A篇有当事人原话，B篇有第三方反应，C篇有后续发展）→ 合并

## 合并写作要点

- 选 content_ja 最丰富的 key 作为主入库 key
- 其他 key 写入 related_keys
- 正文结构：按事件时间线或逻辑层次展开，别把各篇原文拼在一起
- 密度豁免：多篇原文合并后分母变大，密度通常偏低（20-27%）。走"综合采访/多方报道"豁免路径，手动判断信息增量是否充足

## 7/6案例：大岛麻衣约会钱包争议

1. 628c16ca — 大岛麻衣发言+网友反应（956字）
2. 1fc45c8c — 同事件另一报道，补充中嶋优月/杉本彩观点（1088字）
3. 52eb84d1 — 真栄田贤的AA指名清单（563字）

合并后结构：
- 大岛发言（素材1）
- 评论区炸锅（素材1+2的网友评论）
- 真栄田贤蹭热点（素材3）
- 拉远看：两年前的中嶋vs杉本争论（素材2）

written to key 628c16ca，related_keys关联另外两条。

## 7/15案例：对立观点碰撞型合并（大岛麻衣 vs 小仓优子 vs 深田咏美）

当两篇同日素材围绕**同一议题但持对立立场**时，合并为争议型稿件效果极好——天然的三方观点对撞结构，不需要编辑额外制造冲突感。

### 本次合素材

| 素材 | key | 立场 | ts |
|------|-----|------|----|
| 大岛麻衣「约会时女生别掏钱包」 | f5021db6... | 主张男生付 | 5.0 |
| 小仓优子教女儿「AA制好/让人请客不是好女生」+ 深田咏美「男生付」 | 9a596bae... | 主张AA（小仓）/ 主张男生付（深田） | 5.0 |

### 判定流程

1. 通读两篇content_ja → 确认是同一议题的不同立场报导（大岛说女生不该掏钱包、小仓教女儿别让人请客、深田说男生付）
2. 三篇不是重复报道，是**同一议题的多角度呈现** → 适合合并
3. 选大岛麻衣key做主入库key（素材最丰富，3522字），小仓优子key写入related_keys

### 写作结构（对立观点型）

```
[标题含对比]
## 大岛麻衣教女生不掏钱包，小仓优子教女儿别让人请客

### 大岛麻衣：约会时女生不该拿钱包
（直接引语 + 具体主张）

### 小仓优子的回答截然相反
（对立立场 + 教孩子的理由）

### 深田咏美：男生付，天经地义？
（第三方观点，虽然立场和大岛一致但增加了讨论热度）

### 谁说的对？其实不是对错问题
（收束：不站队，呈现价值观匹配问题）
```

### 要点提炼

- **开场定调**：第一段直接点明「同一议题、截然相反的答案」，制造冲突
- **各段独立引语**：每方都给出原话和理由，不做价值判断
- **结尾不升华**：用「价值观匹配问题」收束，不偏向任何一方
- **related_keys双向互设**：大岛key设related_keys=小仓key，小仓key也设related_keys=大岛key
- **关键词密度**：多素材合并后原文基数增大，按综合报道豁免——只要信息增量充足（各素材独有的内容），即使<30%也可以入库

### 适用场景判断

▫️ 同议题对立观点 → ✅ 强力推荐合并
▫️ 同事件互补角度 → ✅ 推荐合并
▫️ 同事件重复报道 → ❌ 不合并，选最长素材写单篇
