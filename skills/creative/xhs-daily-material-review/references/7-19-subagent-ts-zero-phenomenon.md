# Subagent ts=0 现象记录（7/19 首次发现）

## 现象

在并行 delegate_task 分发中，layer23 子 agent 调用 `/api/news?date_from=2026-07-19&limit=200` 时，所有返回记录的 `title_score` 字段均为 0。

**原始报告：** layer23 写道「由于API返回的ts字段均为0，使用以下标准自行分级：S级: cj_len>=500 + 事件型/有故事深度 + 素材充实」

## 同期 layer1 的数据

layer1 在同一次运行中（先于 layer23 几秒执行）获取到正常的 ts 值：
```
高山一实 ts=5.0, 伊藤百花 ts=5.0, 杰西 ts=5.0, Snow Man ts=5.0
坂口杏里 ts=5.0, ITZY ts=5.0, 音楽の日 ts=5.0, 宫胁咲良 ts=5.0
```

即 **layer1 拿到了正常 ts，layer23 拿到的全是 0**。

## 推测根因

可能与并行分发的时机有关 — layer1 先于 layer23 几秒发出请求，触发了 API 的 ts 计算缓存。layer23 的请求发生时 ts 尚未写入缓存或缓存已过期但未重建。不是数据库层面的错误，而是 API 服务端的计算时序问题。

## 影响与应对

| 方面 | 影响 |
|------|------|
| **S级判定** | layer23 改用 cj_len≥500 + 事件性标准。7/19 结果：layer1 8 S vs layer23 7 S。差异在合理范围（15%） |
| **A级判定** | layer23 将部分 A 级降为 B，部分 B 级升为 S（如 ≠ME 从 B→S） |
| **价值建议** | layer23 在 ts=0 时的分析可参考，但引用时应标注「基于自行分级」 |

**应对措施已在主 skill 文档化。**
