# Markdown 表格格式标准（for Telegram sendRichMessage）

## 为什么重要

review 存档文件通过 `sendRichMessage` + `rich_message.markdown` 发送。
Telegram 的 Markdown 解析器**只有识别标准 Markdown 表格**时才会渲染为可视表格（type: table, bordered, striped）。
任何不标准写法都会退化为纯文本 `|` 管道符。

## 标准 Markdown 表格（必定识别 ✅）

```markdown
## 标题（用 ##，不用 **粗体**）

| 列名1 | 列名2 | 列名3 |
|-------|-------|-------|
| 值1   | 值2   | 值3   |
| 值4   | 值5   | 值6   |
```

**关键要求：**
- ✅ `|` **在行首**，无前导空格
- ✅ **分隔行必须存在**（`|---|---|---|`）——没有分隔行一定不被识别为表格
- ✅ 表格前后各一个空行
- ✅ 列数一致（所有行包括分隔行 `|` 数量相同）
- ✅ 表格之前用 `## 标题`（heading block），不是 `**粗体**`（paragraph block）
- ❌ 不要用 `| 列名 | 列名 |` 前加空格

## 常见错误格式（一定不识别 ❌）

### ❌ 无分隔行
```
| 列名1 | 列名2 |
| 值1 | 值2 |
```
→ 被当成纯文本 `|` 管道

### ❌ 分隔行和表头在同一行
```
S级 | 标题 | 理由 | |----|------|
```
→ 不是标准表格，被当纯文本

### ❌ 每行列数不一致
```
| ID | 标题 |
|----|------|-------|
| 1  | 名字 | 多余值 |
```
→ 定位可能出错或渲染为纯文本

### ❌ 表格前无空行
```
文字文字
| 列名 | 列名 |
```
→ 前一段落被合并进表格，破坏结构

## 存档中的具体场景

### 分级结果表

正确写法：
```markdown
### S级（强烈推荐）🔥

| ID | 标题 | 理由 |
|----|------|------|
| 2692 | 佐久间大介借宫馆 | 团爱+趣味 |
| 2691 | Snow Man | 少女漫画反差 |
```

**不要写成：**
```markdown
S级（强烈推荐）🔥 | ID | 标题 | |----|------| | 2692 | ...
```

### 发布方式分析表

正确写法：
```markdown
## 发布方式分析

| 模式 | 条数 | 平均阅读 | 平均互动 |
|------|------|----------|----------|
| rewritten | 14 | 851 | 21.6 |
| normal | 22 | 1,874(含35Koutlier) | 26.0 |
```

**不要写成：**
```markdown
**发布方式分析：**
| 模式 | 条数 | 平均阅读 | 平均互动 |
（即使表格本身标准，但前导**粗体**代替##也会干扰渲染）
```

### 关联类型判断表

正确写法：
```markdown
| 关联类型 | 含义 | 处置 |
|---------|------|------|
| 纯重复 | 同一新闻 | 跳过 |
| 新角度 | 不同侧面 | 写新篇 |
```

## 快速自查清单

写存档时逐条检查：
- [ ] 每个表格前有 `##` 标题（不是 `**粗体**`）
- [ ] `|` 在行首无前导空格
- [ ] 分隔行（`---|---`）存在且列数对齐
- [ ] 所有数据行列数一致
- [ ] 表格前后有空行
- [ ] 所有列的对齐标记 `:---` 至少需要 `---`

## 如果表格数据不适合表格怎么办

对于简单的键值对或单列数据，用 Markdown 列表（`- ` 或 `1. `）更好——列表总是能正确渲染。

例如分级结果如果每行结构很简单，用列表比表格更安全：
```markdown
### S级（强烈推荐）🔥

- **#2692** 佐久间大介借宫馆 — 团爱+趣味，今日最佳
- **#2691** Snow Man佐久间 — 少女漫画反差，标题分5.0
```
