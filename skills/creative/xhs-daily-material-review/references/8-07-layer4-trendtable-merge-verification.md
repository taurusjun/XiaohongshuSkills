# 8/7 layer4 趋势表去重合并 + 主进程验证配方

## 背景

8/4 规范要求「跨会话趋势表」是文件末尾**唯一一张表**。8/7 layer4 子 agent 执行时发现文件中积累了 **9 个重复的「## 跨会话趋势表」节**（8/3、8/4 各自新建节导致），将其合并为文件末尾唯一一张表（保留标准表头 `| 日期 | 新增模式 | 来源数据 | 说明 |`），并删除第7行孤立损坏趋势行（`||| 2026-07-16`，与7/16趋势行重复）。文件 1037 行 → 926 行（-11%）。

**结论：文件行数大幅缩水 = 子 agent 做了去重合并，属正常维护，不是数据丢失。** 但主进程必须验证旧模式仍在。

## 主进程验证配方（layer4 返回后必做）

```bash
PATTERNS=~/.hermes/skills/creative/xhs-daily-material-review/references/data-feedback-patterns.md
wc -l "$PATTERNS"                       # 行数（大幅缩水=合并去重，正常）
grep -c '^## 跨会话趋势表' "$PATTERNS"   # 必须 = 1（唯一一张表）
grep -oE '^### [0-9]+' "$PATTERNS" | grep -oE '[0-9]+' | sort -n | tail -1  # 最高模式编号=今日新增号
grep -c '^### 51' "$PATTERNS"           # 抽查旧模式仍在（>0）
tail -6 "$PATTERNS"                     # 最后一行应为今日趋势行
```

## 关键坑：抽查旧模式的 grep 写法

8/7 主进程第一次抽查用 `grep -n '^\* \*\*#51\|^\* \*\*#100\|...'` 返回 0，差点误判「旧模式丢失」。实际文件模式定义格式是 `### 51. 水川堇...`（行首 `### 数字.`），不是 `* **#51` 列表格式——**是 grep 模式写错，不是数据丢失**。

- ✅ 用行首锚定 `grep -oE '^### [0-9]+'`（与 audit Step 3 一致）或 `grep -c '^### 51'`
- ❌ 不要用 `^\* \*\*#51` / `#51` 裸搜（`#51` 会误匹配正文中的 token）
