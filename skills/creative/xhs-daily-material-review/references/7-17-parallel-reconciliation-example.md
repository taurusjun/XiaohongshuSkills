# 7/17并行分类不一致的汇总示例

## 场景

2026-07-17 的每日素材review中，3层并行 delegate_task（Layer 1 / Layer 23 / Layer 4 同时分发）。Layer 1 和 Layer 23 分别自行拉取今日全量素材并进行 S/A 分级，结果产生了明显的不一致。

## 关键差异类型

### 类型1：ts以外の要因によるS级升降（4件）
L23 几乎完全依赖 `title_score >= 5.0` 判定S级，而 L1 额外考虑了：
- **story 格式**（富田铃花/松下洸平 → story型有物语弧）
- **社会问题属性**（雄乃ゆめ cj=5837 → 内容深度取代ts）
- **内容质量**（市川京子 cj=489略低于500但内容重要）

### 类型2：排除规则的适用（3件）
L1 应用了三类 S 级排除规则，L23 未应用：
- **非対象ジャンル**：BTS（纯音乐/经济类目）
- **晒し系**：能年玲奈（ルック批評/八卦争议，无事件弧）
- **話題爆發性低**：胜又春（天气科普，非事件型）

### 类型3：ts阈值放得太宽（L23 5件S vs L1 6件S）
L23 的 S 级完全基于 `ts>=5.0`，而 58 条素材中有 18 条 ts>=5.0（31%）。按 L23 的逻辑可产生 18 条 S 候选，但实际只选了 5 件——说明 L23 也做了主观筛选，只是筛选标准与 L1 不同。

## 主进程汇总做法

1. **优先信任 Layer 1** — 因为 Layer 1 的 skill 包含了更细致的排除规则和 S 级门槛定义
2. **Layer 23 的价值建议按「建议」引用** — 即使层级标签不同，价值建议本身（标题方向、写法建议）基本独立于层级判定
3. **标注分类差异** — 在存档中注明「Layer 23 将 X 定为 S 级但 Layer 1 按排除规则降级」
4. **Layer 23 的 search 结果独立使用** — 跨时间关联分析（第3层）不受分级影响，每个素材的 search 结果独立有效

## 结论

并行 delegate_task 模式中，分类不一致是固有的——因为两个子 agent 独立拉取数据、独立判定。这不是 bug，而是并行架构的固有特性。主进程的设计必须：
- 明确指定**哪个层是分类权威**（推荐 Layer 1，因为它执行了完整的排除规则流程）
- 不「合并」两套分类，而是选择一套为主、另一套为参考
- 第3层 search 结果保持独立使用（不受 S/A 标签影响）
