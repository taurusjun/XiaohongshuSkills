# 并行模式下 Layer 1 vs Layer 23 作用域不对称（7/20首次发现）

## 问题现象

2026-07-20 并行 delegate_task 执行中，Layer 1 和 Layer 23 的 S/A 分级结果系统性不同：

| 维度 | Layer 1 | Layer 23 |
|------|---------|----------|
| 数据范围 | 目标赛道（坂道系+AKB+娱乐女艺人）= **42条** | 全量库存 = **51条** |
| 排除项 | 経済类Snow Man 9条、グラビア/セクシー女優 | 无排除 |
| S级结果 | 3条（全部AKB：小栗有以/新山千春/高桥南） | 7条建议S（含大桥和也/黑牢城/岩本照等非目标） |

## 根因

不是「分类阈值不一致」（即不是两层的 ts>=5.0 定义不同），而是 **作用域不对称**——两个子 agent 分析的素材集合不同。

Layer 1 按 `fetch_by` 和 `category` 做了赛道过滤，排除了経済/グラビア类。Layer 23 没有这个排除规则，使用了全量 51 条。

## 影响

- 主进程汇总时看到不同的 S/A 列表会困惑：「哪个对？」
- 实际上两个都对——只是作用域不同
- 如果不知道范围差异，用户/编辑会以为分级系统有问题

## 应对措施

### 在主进程 goal 中明确约束作用域

Layer 1 goal 应注明：
```
审核范围：目标赛道（坂道系+AKB+娱乐女艺人），経済/グラビア/セクシー女優类排除。
```

Layer 23 goal 应注明（如果希望对齐）：
```
仅分析目标赛道素材（同 Layer 1 范围）。如果需要 content_ja 可拉全量但保持分级仅对目标赛道。
```
或者（如果希望全量）：
```
分析全量51条素材（含非目标赛道），在报告中标注「全量分析，含非目标赛道」。
```

### 在报告中标注数据范围

- Layer 1 报告开头：`**データ範囲：** 2026-07-20（目标赛道42条，非目标9条排除）`
- Layer 23 报告开头：`**データ範囲：** 2026-07-20（全量51条，含非目标赛道）`

### 主进程汇总时分别列出

存档中不要合并为一份 S/A 表格。分别列出：
```
### Layer 1 S级（目标赛道42条）
...
### Layer 23 建议S级（全量51条，含非目标）
...
```

或标注差异：
```
S级（以下3条来自Layer 1目标赛道分析，Layer 23另有4条非目标赛道S级）
```
