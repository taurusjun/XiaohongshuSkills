# 7/23 title_score（ts）全为 None — 回退到 cj_len+事件性分级

## 现象

2026-07-23 的 API 返回中，所有 56 条记录的 `ts`（title_score）字段均为 `None`：

```
ts=0 显示为 None（JSON 中的 null）
```

Layer 1 子 agent 的示例命令中的 `r.get('title_score', 0)` 对这种全 null 情况输出全是 0。

## 实际影响

- 所有 56 条记录在 Python 中显示 `ts=0`
- 但 `title_score`（另一个字段，非 `ts` 别名）全部为 5.0
- title_score 普遍偏高（56 条中大部分 >=3.0），不能作为区分度标准
- Layer 1 子 agent 的判断逻辑：
  - S级判定改用 `cj_len>=500 + 事件型属性 + 排除规则` 三个标准
  - ts 阈值（>=5.0）因全 null 而失效
  - title_score 作为辅助参考（全部 5.0 时无区分度）
- 结果：8 条 S 级（合理，在 15% 上限内），与历史模式的判断一致性良好

## 根因推测

API 的 `ts` 字段可能依赖于某种后端计算（缓存/批处理），在某些时间段未运行。7/23 的 ts=None 与 7/19 的子 agent 获取 ts=0 的现象类似，但区别在于：

| 现象 | ts=0（7/19） | ts=None（7/23） |
|------|-------------|-----------------|
| 值 | 0（整数零） | null（缺失） |
| 原因推测 | 并发请求时缓存/计算缺失 | 后端批处理未执行 |
| 影响 | 全部 0，无区分度 | 全部 None，无区分度 |

## 应对方法

当意识到 ts 全部为 None 时：
1. 立即在报告开头标注「⚠️ ts 本日全为 None，分级基于 cj_len + 事件性判断」
2. 依赖 cj_len 作为硬阈值（>=500 是 S 级候选），辅以事件性/话题爆发属性
3. 保留排除规则（グラビア、商务合作、晒照照常降级）
4. 输出时明确标注分级依据
5. 不因 ts 缺失而放宽 S 级数量（仍守 10-15% 上限）
